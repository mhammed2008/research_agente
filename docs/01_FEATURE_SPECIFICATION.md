## 2. Detailed Feature Workflows

### 2.1 Contactless Tap & Confirmation (`FEAT-01` & `FEAT-02`)

```mermaid
sequenceDiagram
    autonumber
    actor Customer as Customer (HCE Mobile)
    actor Merchant as Merchant (POS Terminal)
    participant API as API Router (/api/nfc)
    participant Ledger as LedgerService
    participant Crypto as Crypto Vault
    participant Store as SQLite / Memory Store
    participant Hub as TransactionHub

    Merchant->>API: POST /api/nfc/challenge {merchant_id, amount}
    API->>Store: CreateChallenge (nonce, TTL 60s)
    API-->>Merchant: 200 OK (nonce)
    Merchant->>Customer: Transmit Nonce via NFC RF Field
    Customer->>Customer: Derive Session Key & Compute HCE ARQC
    Customer->>Merchant: Send DPAN, ATC, ARQC Cryptogram
    Merchant->>API: POST /api/nfc/pay {dpan, atc, nonce, cryptogram}
    API->>Ledger: TransferViaNfcAdvanced(params)
    Ledger->>Crypto: VerifyHceArqc(sessionKey, challengeVector)
    Crypto-->>Ledger: Cryptogram Valid (Constant-Time)
    Ledger->>Store: CreateTransaction (Status: PENDING_CONFIRMATION)
    API-->>Merchant: 200 OK (PENDING_CONFIRMATION, tx_ref)
    
    par Merchant Long-Polls Status
        Merchant->>API: GET /api/nfc/status?ref=tx_ref&wait=30
        API->>Hub: Subscribe(tx_ref)
    and Customer Authorizes
        Customer->>API: POST /api/nfc/confirm {tx_ref, confirm_code}
        API->>Ledger: ConfirmPayment(tx_ref, confirm_code)
        Ledger->>Store: Atomic Balance Transfer & Update Status COMPLETED
        Ledger->>Hub: Publish(tx_ref, COMPLETED)
    end
    
    Hub-->>Merchant: 200 OK (COMPLETED Receipt)
    API-->>Customer: 200 OK (COMPLETED Receipt)
```

### 2.2 Automated Transaction Reversal (`FEAT-07`)

When a merchant terminal experiences a printer jam, network timeout, or customer cancellation after approval, the terminal dispatches a reversal:

```mermaid
sequenceDiagram
    autonumber
    actor Merchant as POS Terminal
    participant API as Wallet Controller (/api/wallet/transactions/reverse)
    participant Ledger as LedgerService
    participant Store as Database Store

    Merchant->>API: POST /api/wallet/transactions/reverse {ref, reason}
    API->>Ledger: ReversePayment(ref, reason)
    Ledger->>Store: GetTransactionByRef(ref)
    Store-->>Ledger: Transaction Record (Status: COMPLETED)
    Ledger->>Store: ReverseTransaction(ref, reason)
    Note over Store: BEGIN IMMEDIATE TRANSACTION<br/>Debit Merchant Balance<br/>Credit Customer Balance<br/>Insert REVERSAL Record<br/>COMMIT
    Store-->>Ledger: Reversal Transaction Created
    Ledger-->>API: Success
    API-->>Merchant: 200 OK (Restored Balances & Reversal Reference)
```

### 2.3 User-Scoped Transaction Isolation (`FEAT-10`)

1. **Authentication**: Client presents `Authorization: Bearer <user_id>|<hash>`.
2. **Context Resolution**: Middleware parses user identity.
3. **Authorization Check**:
   - If user is `IsAdmin == true`: Permitted to query any user's logs (`/api/wallet/transactions?user_id=X`).
   - If user is non-admin: Restricted strictly to their own account. Querying `?user_id=Y` triggers an instant `403 Forbidden` response.
4. **SQL Execution**:
   ```sql
   SELECT id, ref, sender_id, receiver_id, amount, currency, status, created_at
   FROM transactions
   WHERE sender_id = ? OR receiver_id = ?
   ORDER BY id DESC LIMIT ?
   ```
