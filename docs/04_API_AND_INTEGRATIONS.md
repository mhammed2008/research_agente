## 1. Authentication & Security Conventions

All secured API endpoints authenticate callers via Bearer token:
```http
Authorization: Bearer <USER_ID>|<SESSION_HASH>
```
- **Public Endpoints**: `/api/auth/register`, `/api/auth/login`, `/api/nfc/challenge`, `/api/nfc/pay`, `/api/nfc/confirm`, `/api/nfc/cancel`, `/api/nfc/status`, `/api/nfc/events`, `/api/nfc/apdu`.
- **Authenticated User Endpoints**: `/api/auth/me`, `/api/auth/logout`, `/api/wallet/my-transactions`, `/api/wallet/transactions/confirm`, `/api/wallet/transactions/reverse`, `/api/wallet/topup`.
- **Super Admin Endpoints**: `/api/admin/*`, `/api/wallet/users`, `/api/wallet/transactions` (when accessing arbitrary user records).

## 2. API Endpoint Directory

### 2.1 Authentication & Profile (`/api/auth/*`)

#### `POST /api/auth/register`
Creates a new customer or merchant account.
- **Request Body**: `{"name": "Alice", "email": "alice@teknokeys.com", "phone": "+1-555-0101", "password": "secretpassword"}`
- **Success (200 OK)**: `{"status": "SUCCESS", "token": "2|hash...", "user": {...}}`
- **Errors**: `400 Bad Request` (Missing fields or email/phone conflict).

#### `POST /api/auth/login`
Authenticates a user and generates a session token.
- **Request Body**: `{"identifier": "alice@teknokeys.com", "password": "secretpassword"}` (Accepts email or phone).
- **Success (200 OK)**: `{"status": "SUCCESS", "token": "2|hash...", "user": {...}}`
- **Errors**: `401 Unauthorized` (Invalid credentials or suspended account).

#### `GET /api/auth/me`
Retrieves the authenticated profile.
- **Headers**: `Authorization: Bearer <token>`
- **Success (200 OK)**: `{"status": "SUCCESS", "user": {...}}`

#### `POST /api/auth/logout`
Revokes the current session token immediately.
- **Headers**: `Authorization: Bearer <token>`
- **Success (200 OK)**: `{"status": "SUCCESS", "message": "تم تسجيل الخروج وإبطال الرمز بنجاح"}`

#### `POST /api/auth/card-provisioning`
Enrolls an NFC card credential for an authenticated user.
- **Request Body**: `{"user_id": 2, "card_uid": "04A1B2C3D4E5F6", "master_key": "hex128", "auth_key": "hex128"}`

### 2.2 NFC & Contactless Protocol (`/api/nfc/*`)

#### `POST /api/nfc/challenge`
Generates an unpredictable single-use 64-bit cryptographic challenge nonce.
- **Request Body**: `{"merchant_id": "MRCH-YE-770412", "amount": "25.00", "currency": "YER"}`
- **Success (200 OK)**:
  ```json
  {
    "status": "SUCCESS",
    "nonce": "7A8B9C0D1E2F3A4B",
    "challenge": {
      "nonce": "7A8B9C0D1E2F3A4B",
      "amount": "25.0000",
      "currency": "YER",
      "expires_at": "2026-09-25T18:45:00Z"
    }
  }
  ```

#### `POST /api/nfc/pay`
Processes contactless tap data. Always initiates two-phase confirmation (`PENDING_CONFIRMATION`).
- **Request Body**:
  ```json
  {
    "tokenized_dpan": "4921880019248810",
    "merchant_id": "MRCH-YE-770412",
    "terminal_id": "TERM-0001",
    "amount": "25.00",
    "currency": "YER",
    "atc": 13,
    "nonce": "7A8B9C0D1E2F3A4B",
    "cryptogram": "8f3b2a1c9d4e5f60",
    "rtt_ms": 115
  }
  ```
- **Success (200 OK)**:
  ```json
  {
    "status": "PENDING_CONFIRMATION",
    "requires_confirmation": true,
    "data": {
      "transaction_ref": "tx_c8f921da-0d48-4389-a35b-117215918731",
      "confirmation_token": "cf_9941a39a-7612-4cf0-bb4b-32eb4a7f05b9",
      "confirm_code": "829401",
      "amount": "25.00",
      "expires_in_seconds": 300
    }
  }
  ```
- **Errors**: `422 Unprocessable` (Monotonicity failure, expired nonce, relay RTT > 500ms, velocity limit).

#### `POST /api/nfc/confirm`
Customer confirms and authorizes settlement of a pending transaction.
- **Request Body**: `{"transaction_ref": "tx_c8f921da...", "confirm_code": "829401"}`
- **Success (200 OK)**: `{"status": "COMPLETED", "data": {...}}`

#### `POST /api/nfc/cancel`
Customer declines a pending transaction before confirmation.
- **Request Body**: `{"transaction_ref": "tx_c8f921da...", "confirmation_token": "cf_9941a39a...", "reason": "User cancelled"}`
- **Success (200 OK)**: `{"status": "CANCELLED", "data": {...}}`

#### `GET /api/nfc/status`
Queries or long-polls for transaction status changes.
- **Query Params**: `ref=tx_...`, `wait=30` (holds open up to 30s).
- **Success (200 OK)**: `{"status": "COMPLETED", "data": {"is_final": true, ...}}`

#### `GET /api/nfc/events`
Server-Sent Events (`text/event-stream`) stream pushing status updates to terminals.
- **Query Params**: `ref=tx_...`

#### `POST /api/nfc/apdu`
Direct ISO/IEC 7816-4 APDU command channel (`SELECT AID` and `GENERATE AC`).
- **Request Body**: `{"apdu": "00A4040006F0010203040500"}`
- **Success (200 OK)**: `{"status": "SUCCESS", "response_apdu": "9000", "sw": "9000"}`

### 2.3 Wallet & Transactions (`/api/wallet/*`)

#### `GET /api/wallet/my-transactions`
Retrieves the authenticated user's personal transaction history.
- **Headers**: `Authorization: Bearer <token>`
- **Success (200 OK)**: `{"status": "SUCCESS", "transactions": [...]}`

#### `GET /api/wallet/transactions`
Global ledger view (Super Admin) or user self-query. Non-admin queries for other accounts return `403 Forbidden`.
- **Query Params**: `user_id=2`, `limit=50`

#### `POST /api/wallet/transactions/confirm`
Authenticates transaction confirmation via active session token.
- **Headers**: `Authorization: Bearer <token>`
- **Request Body**: `{"transaction_ref": "tx_c8f921da..."}`

#### `POST /api/wallet/transactions/reverse`
Executes an automated POS reversal for a completed transaction.
- **Request Body**: `{"ref": "tx_c8f921da...", "reason": "Terminal timeout"}`

#### `POST /api/wallet/topup`
Adds funds to a wallet balance.
- **Request Body**: `{"user_id": 2, "amount": "100.00"}`

#### `POST /api/wallet/hce/provision`
Provisions an HCE software profile for a mobile device.
- **Request Body**: `{"user_id": 2, "device_fingerprint": "ALICE-PIXEL8"}`
- **Success (200 OK)**: Returns assigned `tokenized_dpan` and `jaib_aid`.

---

### 2.4 Merchant Acceptance (`/api/wallet/merchant/*`)

#### `POST /api/wallet/merchant/activate`
Upgrades an active user account to an accepting merchant.
- **Request Body**: `{"user_id": 3, "business_name": "Bob Supermarket", "mcc": "5411"}`
- **Success (200 OK)**: Assigns generated `merchant_id` (e.g. `MRCH-YE-770412`).

#### `POST /api/wallet/merchant/terminals`
Registers a POS hardware terminal or mobile phone register under a merchant.
- **Request Body**: `{"user_id": 3, "terminal_name": "Checkout Lane 1"}`
- **Success (200 OK)**: Assigns unique `tid` (e.g. `TERM-821941`).

#### `GET /api/wallet/merchant/profile`
Fetches merchant profile and enrolled terminals by MID.
- **Query Params**: `mid=MRCH-YE-770412`

### 2.5 Admin Governance (`/api/admin/*`)

#### `GET /api/admin/metrics`
Super admin metrics: total users, merchants, active terminals, transaction volumes, and system balances.
- **Headers**: `Authorization: Bearer <ADMIN_TOKEN>`

#### `POST /api/admin/users/balance`
Administrative balance adjustment (CREDIT or DEBIT).
- **Request Body**: `{"user_id": 2, "amount": "50.00", "action": "CREDIT", "reason": "Promotional bonus"}`

#### `POST /api/admin/users/status`
Suspends or unlocks an account (`active`, `suspended`, `locked`).
- **Request Body**: `{"user_id": 2, "status": "suspended"}`

#### `POST /api/admin/users/rotate-keys`
Rotates master derivation keys and NFC credentials.
- **Request Body**: `{"user_id": 2}`

#### `POST /api/admin/transactions/refund`
Executes an administrative refund for a transaction.
- **Request Body**: `{"transaction_ref": "tx_c8f9...", "reason": "Customer dispute resolution"}`
